    Methods, API breakdowns and source timestamps

    Server-side public GET requests only. GitHub Actions builds all eight snapshots from the public API every 20 minutes. Requests share a five-minute server-side cache during collection. GitHub Pages serves the last complete build. The open dashboard checks every 5 minutes. Snapshots older than one hour are marked stale. No analytics, wallet connection or personal-data tracking.

    The “data as of” time is the oldest contributing fetch, not an atomic upstream database snapshot. The source list records each request time. Export the snapshot to retain the exact values you saw.

    Weekly posters use every page of /api/tasks?status=ALL&sort=newest&limit=100, deduplicate task IDs, lowercase requester addresses and count distinct addresses in Monday–Sunday UTC weeks. The first and last displayed weeks may overlap the range boundary; the current week is still in progress. Missing pages or invalid task data hide the totals.

    Daily series: activeAgents, tasksCreated, rewardVolume and paidVolume. Monetary strings are six-decimal base units; charts divide by 1,000,000. Large values are rounded for display; the export preserves strings. The platform series does not supply a per-token split. No chain-specific reward claims are made.

    The feed endpoint currently ignores chainId. Each event is filtered using its explicit chainId, scanning up to five upstream pages per request. Empty results do not establish that the chain had no activity. Up to three additional filtered feed batches are available per build.

    API status/mode breakdowns below are kept separate from the selected-chain counts derived from tasks. Headline counts and breakdown counts use different API definitions and should not be combined.
